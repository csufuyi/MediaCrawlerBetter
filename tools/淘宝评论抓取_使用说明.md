# 淘宝/天猫 商品评论抓取器（tools/taobao_rate.py）

MediaCrawler 官方不支持淘宝。本工具补上「淘宝商品评论」这一块，用的是和
MediaCrawler 相同的思路：**不滚动抓评论 DOM，而是用登录态自己算 mtop 签名，
直接调 JSON 评论接口** `mtop.taobao.rate.detaillist.get`。

## 为什么用这个思路（实测结论）

淘宝有两道墙：
1. **地域墙**：海外 IP 下所有商品详情页跳「此商品不可运送」，滚 DOM 抓评论直接死。
2. **签名 + 风控**：评论接口要 `_m_h5_tk` token + md5 签名。

签名接口这条路**同时绕过了地域墙**（`h5api.m.taobao.com` 不做地域限制），
浏览器实测已返回真实评论数据。Python 侧用 `curl_cffi` 模拟 Chrome TLS 指纹过风控。

## 用法

### 1. 准备登录 cookie（关键）

评论接口需要**真实登录态**，否则会返回 `RGV587_ERROR::SM::被挤爆啦`（风控拦截）。

- 用**已登录淘宝**的 Chrome 打开任意淘宝页面；
- F12 → Network → 随便点一条发往 `*.taobao.com` 的请求 → 右键 → Copy →
  **Copy request headers**，找到 `Cookie:` 那一行，复制**整段** cookie 值；
- 粘贴进 `tools/taobao_cookies.txt`（该文件已加入 .gitignore，不会被提交）。

> ⚠️ 必须从「请求头」复制，因为登录 cookie（cookie2 / _tb_token_ / sgcookie / unb 等）
> 是 httpOnly 的，`document.cookie` 读不到。

### 2. 拿商品 ID

商品链接 `item.taobao.com/item.htm?id=627338948826` 里的 `id=` 就是。
搜索页也能批量取（每个商品卡片的链接里都有 `id=`）。

### 3. 运行

```bash
cd /Users/weisheng/MediaCrawler

# 单个商品，抓 5 页
uv run tools/taobao_rate.py --item-id 627338948826 --max-pages 5

# 多个商品，翻页间隔 3 秒，指定输出
uv run tools/taobao_rate.py --item-ids 627338948826,621840569465 --sleep 3 --out data/眼霜评论.xlsx
```

输出 Excel 字段：`item_id, rate_id, content(评论正文), append(追评), sku, date, user, useful, pics`。

## 防风控要点（默认已按最保守配置）

- **单线程 + 每页 sleep**（默认 3 秒），别调太快；
- **只抓一级评论**（追评随主评论一起返回，不额外发请求）；
- 出现 `RGV587` / 验证 → **停下**，隔一段时间再试，或先在浏览器里手动过一次验证刷新 cookie；
- cookie 会过期，失效了重新按第 1 步导出。

## 参数

| 参数 | 说明 | 默认 |
|---|---|---|
| `--item-id` / `--item-ids` | 单个 / 多个商品 ID（逗号分隔） | 必填其一 |
| `--max-pages` | 每个商品最多抓多少页 | 5 |
| `--page-size` | 每页评论数 | 20 |
| `--sleep` | 翻页间隔秒数（降速防风控） | 3 |
| `--cookie-file` | cookie 文件路径 | tools/taobao_cookies.txt |
| `--out` | 输出 Excel 路径 | data/taobao_rates.xlsx |

⚠️ 仅供个人学习/研究，遵守平台条款，控制频率，勿大规模抓取。
